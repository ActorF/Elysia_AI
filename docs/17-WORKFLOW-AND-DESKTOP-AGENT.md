# Work 工作流与桌面能力

Work 支持模型规划工具和 CMD 命令，也保留显式计划、单次文件写入批准和检查点恢复。每次执行都绑定当前会话及用户选择的权限；结构化文件工具遵守 Workspace 边界，通用 CMD 使用当前 Windows 用户权限。

## 对话思考与权限

模型右侧可切换深度思考，并为本轮选择权限：

| 权限 | 能力 |
| --- | --- |
| 仅对话 | 不调用工具 |
| 只读 | 在选定 Workspace 内查找、列目录、读取文本及元数据；查看支持的应用与系统音量 |
| 操作前询问 | 只读能力；CMD 在输入区的生成按钮上方逐条确认，应用启动和音量调整使用原生确认；默认选择 |
| 允许桌面操作 | 自动执行上述受支持桌面动作，不提供任意命令或管理员权限 |
| 允许 CMD 命令 | 模型可直接运行通用 CMD 命令和桌面工具；命令能够读写文件、运行程序及联网，不自动提升管理员权限 |

Windows 应用目录目前包括记事本、计算器、画图和文件资源管理器；只启动已验证系统路径，不接受模型提供的程序路径或参数。音量操作使用默认输出设备的 Core Audio 接口，确认前后核对设备，保留静音设置并读取实际结果。

`chat.work` 在同一次生成内最多执行八个工具调用，再用真实回执生成回复。权限在发送时固定，模型请求由 Python 与 Main 分别校验。结构化文件写入仍走下方的显式计划和批准；CMD 引起的文件变化不属于该事务恢复机制。重新生成只重答，不重放工具。Voice Call 不继承桌面操作权限。

深度思考显示明确的开关状态，使用本轮 Ollama thinking 参数；不支持时明确报错。对话内以紧凑记录显示当前阶段与工具结果，最近文件变更来自当前 Chat 的操作历史，只展示已确认完成的变更与撤销。Main 在当前应用会话保留最近过程以供窗口刷新恢复，关闭应用后不保留；权限选择刷新后恢复默认。Project Sources 与对话工具/深度思考分别使用，避免隐式混用。

## 通用 CMD 执行

在 Work 中选择 **允许 CMD 命令** 后，可以直接提出“检查 Windows 版本、内存和运行中的进程”等任务。模型自行生成命令，读取实际输出，再决定下一步或生成回答；不要求为每类问题提前编写专用工具。选择 **操作前询问** 时，输入区的生成按钮上方会显示待执行命令，提供 **Yes / No**。可以展开核对完整命令和工作目录，点击 Yes 后才运行；No 拒绝本次命令。停止任务、切换所有者或确认超时会撤销待确认请求，旧按钮不能继续批准。

界面可展开查看实际命令、工作目录、标准输出、错误输出、退出码和截断标记。非零退出不会显示为成功；模型可以根据错误调整命令，但拒绝和取消不会触发绕过权限的重试。若本轮只有一条未获授权的 CMD，程序直接确认命令已跳过、没有执行，避免模型编造输出或要求重新授权；若已有其他操作结果，则保留实际回执供模型汇总。命令默认最多运行 30 秒，可指定至 120 秒；两路输出持续读取，合计保留最多 16 KiB，超过时明确标记截断。模型规划和结果上下文也有大小及步数预算。

文本输出支持默认 UTF-8、`cmd /u` 的 UTF-16，以及带 BOM 的 UTF-8／UTF-16／UTF-32；完整换行分隔的 UTF-8／UTF-16 混合输出分别解码。截断会避开残缺字符；任意二进制或无标记的其他编码不能保证自动识别。

命令回执与模型解释分别展示。执行成功不保证本地模型解释正确；例如内核版本号不等于 Windows 产品名称，账号标识也不能证明用户组或管理员权限。需要核对这类结论时，查看原始输出并补充实际查询。

命令通过系统 `cmd.exe` 执行，禁用 AutoRun。命令使用单行文本，多步可用 `&`、`&&` 或调用脚本；拒绝包含换行的命令，防止 CMD 只执行首行却被误认为全部完成。执行为非交互模式，不提供键盘输入。未指定目录时使用用户主目录；指定目录须为盘符绝对路径，不能使用会让 CMD 默默切换到 Windows 目录的 UNC 工作目录。命令参数仍可引用 UNC 文件路径。工作目录不构成文件访问隔离。环境只传递运行常见程序所需的明确变量，不继承应用密钥或后端认证令牌。Windows Job Object 管理普通子孙进程，命令结束、停止、超时或执行器退出时清理进程树，因此此入口不保留后台常驻进程；由系统服务另行启动的任务不在同一进程树保证内。

**CMD 不是沙箱。** 允许 CMD 的权限包含当前 Windows 用户能够执行的文件和网络操作，应用的 Internet 开关不约束 `curl` 等外部程序。CMD 修改没有自动撤销；需要事务预览和恢复时，使用下方的结构化文件工具。权限默认不授予 CMD 自动执行，旧版“允许桌面操作”也不会自动升级为此权限。

## 状态与执行图

`agent/workflow_state.py` 定义版本 1 的严格 JSON 合同：最多 768 KiB、16 步。未知版本、额外字段、重复步骤、不匹配结果及改变原调用的快照均拒绝。

| 记录 | 内容 |
| --- | --- |
| Request | Chat、可空 Project、Work 模式、标题、时间、目录身份和有序调用摘要 |
| Plan / Step | 计划、调用、结果与当前待确认预览 |
| Cursor | 源码定义的节点与当前步骤，不能由模型任意跳转 |
| Result / Error | 终态摘要和固定错误，不保存原始异常或重复正文 |
| Admitted step | 区分预览与已进入写入的步骤，保留取消后的真实效果 |
| Checkpoint | ID、父记录、时间、恢复处置与强制重验标志 |

目录摘要包含规范路径与原生身份，原生 ID 用十进制字符串避免 JavaScript 精度损失。摘要只供比较，不能恢复路径权限。线程、锁、取消函数和物理忙碌状态不持久化。

`agent/work_graph.py` 使用固定路径：

```text
START → admission → memory → rag → brain → approval → tool → verification → END
```

读取分支由 `WorkPlanRunner` 执行；写入先经过建议与批准路由，再进入原有预览和单次批准服务。图只接收有界 JSON，取消函数留在进程内；读取前后检查取消，验证节点核对结果路径。固定边、递归上限和无自动重试限制执行。LangGraph 固定为 1.2.15，并显式关闭 LangSmith tracing，避免环境配置意外导出本地内容。

Memory 限于当前 Chat/Project；RAG 只在创建计划时明确勾选 Project Sources 后运行，继续使用来源权限和版本租约。两类各最多八条、单条正文 4 KiB。Brain 只接收标题与有界上下文，生成最多 8 KiB 的建议，不把建议解析成调用，也不写入 Chat 或长期记忆。缓存按计划隔离，读取和发布都重新检查范围与取消。

[Vision](18-VISION-AND-SCREEN.md) 可为下一份计划提供一份仍有效的审核记录。来源、OCR、模型推测和用户说明分开传递，仅作建议输入；视觉正文和模型建议不进入检查点，重启后不会恢复。

## 写入批准与修改

写入在当前步骤显示预览，可批准、修改或拒绝。批准只消耗一次令牌；拒绝结束计划。修改只允许同一种工具的参数：先审计 `modify` 并撤销旧令牌，再把修改步骤及未完成后续步骤组成新计划。新计划仍需明确 Start、生成预览并取得新批准，已成功步骤不会重放。

有效期同时受 UTC 和单调时钟约束，回拨时间不能延长权限。过期由后台审计结束为 `timeout`，迟到批准不能执行。审计记录 `approve`、`modify`、`reject`、`timeout` 和实际结果，不保存正文或令牌，也不推断旧记录缺少的决定。

修改与取消、导航、关闭共用版本检查。取消胜出后，迟到回调不能重新发布计划；审计或检查点失败不能启动修改后的动作。

## 持久化与恢复

`WorkflowStore` 在 `workspace/work/workflows` 为最多 1000 个 Chat 保存各自最新的严格 JSON 检查点。原生边界拒绝链接、硬链接和目录替换；临时文件刷新后在同目录原子发布。跨进程锁和独立磁盘 CAS 版本阻止旧执行器覆盖新计划；删除 Chat 写入 tombstone，阻止迟到回调恢复任务。

Runner 在步骤开始、写入接纳前和暂停/终态边界保存。存储锁与状态锁分离，慢磁盘不阻止取消。保存失败阻止新的原生写入；已完成操作仍保留真实结果，并另行提示保存失败。

| 恢复状态 | 处置 |
| --- | --- |
| 未开始步骤、中断读取、待批准预览 | 转为暂停；重新核对 Chat、Project、Work 模式、目录和文件状态 |
| 已接纳但结果未确认的写入 | 标记 `uncertain_write`，先检查事务审计与恢复副本，不允许直接重放 |
| 已完成步骤 | 保留真实结果；普通更新不能把终态改回可执行 |

重启后的 `work.plan.get` 只加载与当前范围和重新取得的目录身份一致的数据。用户明确 Resume 后才继续，写入预览和批准必须重建；Project Sources 的选择、批准令牌和视觉上下文不会跨重启继承。不确定写入只显示核对提示，不安装可运行计划。恢复只解析有界 JSON，不反序列化任意 Python 对象。

## 显式桌面工具

桌面操作有独立入口。Main 每次重取规范 Chat、Project、Work 模式与目录；原生忙碌状态参与 Chat、Voice、文件工具、计划、数据迁移和关闭门禁。

| 工具 | 范围 |
| --- | --- |
| 打开文件 | 原生选择器限定 Workspace 内最多 16 MiB 的 txt、md、csv、json、pdf、docx；打开私有审阅副本，外部编辑不改变原件 |
| 打开应用 | 仅 Windows 固定系统目录的 Notepad，空参数；其他平台不可用 |
| 剪贴板 | 点击才读取纯文本；写入先完整预览最多 32 KiB，再取得单次批准 |
| 窗口选择 | 点击才列最多 100 个名称；只公开短期选择 ID，不提供截图、原生句柄或键鼠控制 |

文件在批准前后检查路径、链接、身份、哈希和格式。敏感名称检查包含 Workspace 根目录的全部祖先，给密钥名加文档后缀也不能绕过。原生大整数身份不会转成不精确的 JavaScript Number。

批准与窗口选择最多保留五分钟，范围变化或关闭即撤销。操作前必须保存脱敏审计，失败则不执行；效果发生后审计失败仍如实显示。审计不含正文，最多保留 200 条并提示截断。

私有审阅副本位于 `workspace/work/desktop`，最多 20 份。到上限后拒绝新建，不自动删除可能仍被外部应用使用的文件；用户可通过打开数据目录入口管理。

## 预算、取消与重试

下表适用于显式计划；对话中的 CMD 使用前文说明的单命令期限和八步调用上限。

| 预算 | 限制 |
| --- | --- |
| 总任务 | 默认 300 秒，受信配置最多 900 秒；暂停和等待批准也计时 |
| 单步读取/预览 | 30 秒 |
| 写入接纳 | 20 秒；检查点、预检和备份共用期限，不逐层重置 |

预算从首次执行起算；重启后明确恢复暂停任务会建立新进程内预算。界面显示已完成步骤、剩余时间、阶段和尝试次数。取消、关闭和超时阻止后续接纳；物理任务返回前仍占容量，已进入原生写入的操作继续验证并报告真实结果。Chat/Project 共用保守的写入互斥门禁。

只有因 `timeout` 或 `io_error` 失败的读取提供 **Prepare read retry**，每步最多两次。它保留步骤 ID、参数和剩余预算，只把失败及未完成步骤组成新计划，不自动 Start 或批准。成功步骤不会重放；污染参数、权限拒绝、取消和写入失败不提供该入口。

## 验证与维护

安全测试只用临时目录、合成文件和替身接口，检查实际调用、文件结果与审计。重点覆盖提示注入、参数污染、路径逃逸、文件替换、重复/过期批准、伪造检查点、取消竞争、迟到回调和不确定写入。模型自述不能作为权限验证。

核心测试入口是 `tests/test_workflow_security.py`、`tests/test_workflow_recovery.py`、`tests/test_workflow_job_integration.py`，以及 `desktop/tests/work-desktop-*.test.mjs` 和 `work-job-*.test.mjs`。通用命令另由 `tests/test_work_command_runner.py`、`tests/test_work_assistant.py` 和 `desktop/tests/work-command-native.test.mjs` 验证真实 CMD 语法、中文输出、错误纠正、输出预算及子进程清理。UI 回归覆盖权限选择、真实命令回执、明确 Resume、多步批准/修改、预算、重试和取消排空。

设计参考：[Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)、[Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)、[Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)。恢复会重新进入中断节点，因此副作用必须由本项目的批准与事务边界控制。
