# Work 工作流与桌面能力

Stage 10 在 Stage 9 的显式计划、目录边界和单次写入批准之上加入工作流。现有 `work.plan` 仍是界面显示的执行事实；版本化工作流记录补充请求来源、节点位置和恢复信息。人格 Markdown、图片生成、Chat 消息与私有 Work 数据各自保留原有职责。

## 版本化状态

`agent/workflow_state.py` 定义版本 1 的严格 JSON 合同。未知版本、额外字段、重复步骤、越界内容、不匹配的工具结果或改变原始调用的快照均被拒绝。状态上限为 768 KiB，计划最多 16 步。

| 数据 | 含义与边界 |
| --- | --- |
| Request | 唯一请求、Chat、可空 Project、Work 模式、标题、时间、目录身份摘要和有序工具调用摘要。 |
| Plan / Step | 沿用 Stage 9 的计划、步骤、调用、结果和当前待确认预览。 |
| Cursor | 源码定义的节点名称与当前步骤，不能由模型生成任意跳转。 |
| Result / Error | 终态摘要和固定错误词表，不保存原始异常或重复文件正文。 |
| Admitted step | 区分正在生成预览与已进入本地写入的步骤。取消不能把已经执行的写入伪装成未执行。 |
| Checkpoint | 唯一记录、父记录、保存时间、恢复处置和强制重新验证标志。 |

目录身份摘要包含受信边界的规范路径及原生目录身份。原生 ID 以十进制字符串参与摘要，避免 JavaScript 数字精度损失。摘要只能用来比较；它不是路径，也不能恢复文件系统权限。进程内的线程、锁、取消函数和物理忙碌状态不进入持久化合同。

## 只读执行图

`agent/work_graph.py` 的初始只读图已扩展为固定的 `START → admission → memory → rag → brain → approval → tool → verification → END` 路径。条件边只根据代码验证后的调用决定进入读取工具还是结束并要求批准。`WorkPlanRunner` 的实际读取分支使用这个图，写入先走建议和批准路由，再由原有预览与单次批准服务处理。

图只接收有界 JSON 调用和结果，取消函数放在进程内 context。读取前后都检查取消，验证节点再核对结果的路径与请求一致。递归上限、固定边和无自动重试限制执行；显式关闭 LangSmith tracing，避免环境变量意外把本地文件内容导出。依赖固定为 LangGraph 1.2.15。

Memory 使用当前 Chat/Project 范围，RAG 仅在创建计划时明确勾选 Project Sources 后运行，且仍使用原有来源权限与版本租约。两者每类最多八条记录，单条正文最多 4 KiB。Brain 只接收计划标题和有界上下文，生成最多 8 KiB 的只读建议，不写入 Chat 或长期记忆，也不把建议解析为调用。上下文按当前计划缓存，所有读取与缓存发布都重新检查所属范围和取消状态。

Plan 面板在原有执行事实之外展示当前节点、上下文数量和建议。模型不可用时明确显示未完成分析，显式工具仍由代码权限层处理；检索文本、模型回答和文件内容都不能更改工具调用或批准权。

## 恢复处置

安全的未开始步骤、被打断的读取和待批准预览可以转为暂停记录。恢复仍须重新核对当前 Chat、Project、Work 模式、目录身份和文件状态，并重新生成需要用户确认的写入预览。批准令牌不能跨重启成为权限。

已接纳、但结果尚未确认的写入标记为 `uncertain_write`。此类记录必须先检查原有事务审计及恢复副本，不能直接重放。已完成步骤保留其真实结果；终态不能被普通状态更新改回可执行状态。

`WorkflowStore` 在应用私有 `workspace/work/workflows` 中为每个 Chat 保留最新严格 JSON 检查点，最多 1000 个 Chat 记录。目录和文件通过原有原生边界校验，拒绝链接、硬链接和目录替换；临时文件先刷新，再在同目录原子发布。跨进程锁和独立磁盘 CAS 版本防止旧执行器覆盖新计划或删除标记。删除 Chat 会保存 tombstone，迟到回调不能重新写回被删除的任务。

Runner 在开始步骤、写入接纳前及暂停/终态边界保存检查点。存储锁与逻辑状态锁分离，慢磁盘不阻止正在运行任务的取消。保存失败会阻止新的原生写入；若实际操作已完成，则保留真实结果并另行显示保存失败提示。

重启后的 `work.plan.get` 只加载与当前 Chat、Project 和重新取得的目录身份一致的数据，复用现有 Plan 面板显示暂停任务。用户明确 Resume 后才继续；Project Sources 的选择不会跨重启继承。结果不确定的写入只显示审计核对提示，不安装可运行计划。不通过反序列化任意 Python 对象恢复执行。

## 人工决定

写入预览暂停在当前步骤，界面提供批准、修改或拒绝。批准仅消耗当前步骤的一次令牌；拒绝结束该计划。修改只允许调整同一种工具的参数：旧令牌先作为 `modify` 决定写入审计并撤销，随后建立包含修改步骤和后续未完成步骤的新待开始计划。已成功的读取和写入不会被重放。新计划仍须明确 Start，并生成新的写入预览和批准。

批准有效期同时受 UTC 和单调时钟限制，系统时间回拨不能延长权限。界面轮询待批准或暂停的计划时，会让过期批准通过后台审计步骤结束为 `timeout`；用户迟到的批准同样不能执行。审计分别记录 `approve`、`modify`、`reject`、`timeout` 以及实际结果；旧版本记录没有决定字段时不推断历史决定。读操作没有写入批准决定，审计不保存正文和令牌。

修改期间的创建保留与取消、导航、关闭共用版本检查。取消胜出后，迟到的修改回调不能重新发布计划；审计或检查点失败也不会启动修改后的动作。

## 显式桌面工具

Work 面板提供独立的桌面操作入口。Main 每次重新取得规范 Chat、Project、Work 模式与目录，原生操作占用的忙碌状态也参与 Chat、Voice、文件工具、计划、数据迁移和关闭门禁。模型建议不能调用这些入口或生成批准。

- 打开文件：原生选择器只接受当前 Workspace 内最多 16 MiB 的 txt、md、csv、json、pdf、docx 文档。批准前后检查路径、链接、文件身份、内容哈希和格式；打开的是私有审阅副本，外部应用的编辑不改变 Workspace 原件。
- 打开应用：仅 Windows 固定系统目录的 Notepad，参数为空。其他平台显示不可用。
- 剪贴板：点击才读取纯文本；写入须先完整显示最多 32 KiB 的文本，再取得单次批准。不会定时读取剪贴板。
- 窗口选择：点击才取得最多 100 个窗口名称，用户选择其中一个。名称和短期不透明选择 ID 可显示；原生句柄、截图、缩略图、音频和捕获权限不会交给界面。这里不提供键鼠控制。

批准和窗口选择最多保留五分钟，所属范围变化或关闭会撤销；重复批准不能执行第二次。操作前先保存脱敏审计，保存失败则不执行；原生效果已发生后保存失败，界面仍说明效果与审计失败。审计不含剪贴板或文档正文，最多保留最近 200 条记录，并明确提示截断。

私有数据位于 `workspace/work/desktop`。审阅副本最多保留 20 份，到上限后拒绝继续创建，不自动删除可能仍被外部应用打开的文件。用户可通过界面的打开数据目录入口管理副本。私有目录及副本使用精确原生身份和内容校验；Windows 大整数文件身份不会转换成不精确的 JavaScript Number。

## 长任务预算与显式重试

每个运行任务默认有 300 秒总预算，受信配置上限为 900 秒。读取与预览每步最多 30 秒，写入接纳最多 20 秒。暂停和等待批准都计入总预算；检查点、写入预检与备份共用同一个接纳期限，不能在每层重新计时。预算从首次开始执行起算；明确恢复重启后的暂停任务会建立新的进程内预算。

进度面板显示已完成步骤、剩余总时间、当前阶段与尝试次数。取消、关闭和超时会停止后续接纳，但物理任务仍占用容量直到返回；已经进入原生写入的操作完成验证并显示真实结果。各 Chat 和 Project 共用保守的写入互斥门禁，避免任务、独立工具和桌面操作互相覆盖。

仅因 `timeout` 或 `io_error` 失败的读取提供“Prepare read retry”。每步最多重试两次；用户点击后建立只含失败步骤与未完成后续步骤的新待开始计划，保留原步骤 ID、参数和剩余总预算。已完成的读取或写入不会重放，重试也不会自动 Start 或批准后续写入。参数污染、权限拒绝、取消和写操作失败不提供此重试入口。
